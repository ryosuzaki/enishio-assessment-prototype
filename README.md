# Enishio Assessment Prototype

[![CI](https://github.com/ryosuzaki/enishio-assessment-prototype/actions/workflows/ci.yml/badge.svg)](https://github.com/ryosuzaki/enishio-assessment-prototype/actions/workflows/ci.yml)

生成AIとの協働プロセスの中で立ち現れる **「動的コンピテンシー（動的で不確実な状況下において、AIを含む情報やプロセスを多角的に吟味し、自己の思考を省察・適応させながら、責任を持って課題解決や価値創出を主導する実務判断力）」** を測り、育てるB2B SaaSのプロトタイプです。

B2Bプロダクトとしての利用全体像を示すモックUIと、中核評価エンジンの実稼働を1つのアプリケーションに統合しています。

---

## 1. 何が動いていて、どこがモックか

| 画面・機能 | 稼働状態 | 概要 |
| :--- | :--- | :--- |
| **実務演習セッション** | **LLM・DB連動で実稼働** | 2ペイン動的対話 → 前提変化の自動注入 → CFF事前判定 → 構造化採点パイプライン（2段階採点） → XAI評価レポート |
| **共通アンカー評価** | **出題〜無得点記録まで実稼働** | 医学教育のSCT形式を応用した固定尺度による出題と判断傾向の記録（同梱サンプル3件） |
| **① 組織・受講管理ダッシュボード** | **モックUI** | 組織全体の成長推移、AI鵜呑み率の改善可視化（Prismaスキーマ準拠の静的データ） |
| **② 受講者スキルカルテ** | **モックUI** | 4領域レーダーチャート、適正依存プロファイル、好手ログ |
| **③ エキスパート事後講評** | **モックUI** | AIの欺瞞メカニズム解剖、上位者アプローチとの比較 |

## 2. 画面と演習の流れ

画面上部のタブから5つの画面を自由に切り替えられます。

```
┌───────────────────────────────────────────────────────────────────────────────────────┐
│ [Enishio] 実務演習セッション │ 共通アンカー評価 │ ① 組織ダッシュボード │ ② 受講者カルテ │ ③ エキスパート事後講評 │
└───────────────────────────────────────────────────────────────────────────────────────┘
```

### 2.1 実務演習セッション（中核評価エンジン）

受講者がAI同僚と協働してコードレビューを行い、途中で入る仕様変更に対応し、自身の判定を確定させたうえで、根拠つきの評価レポートを受け取る縦切り1本です。

```
[課題提示・背景確認] ─→ [2ペイン動的対話] ─→ [CFF 事前判定] ─→ [構造化採点パイプライン（2段階）] ─→ [XAI評価レポート]
                              │ (⚡ 緊急仕様変更の注入 ← 進行役が自動で撃つ)
```

| ステップ | 名称 | 受講者の体験 |
| :--- | :--- | :--- |
| **1** | **課題提示・背景確認** | 実務課題（決済セキュリティ／在庫並行処理／チケット自動割当）を選び、受入基準や重点観点を確認して開始。 |
| **2** | **2ペイン動的対話** | 画面上でAI同僚と協働レビュー。初期方針が固まった時点で進行役が緊急仕様変更（前提変化）を自動注入し、適応力を観測。 |
| **3** | **CFF（認知強制機能）** | AI採点の開示前に、成果物をGitHub PRレビュー準拠の3択（［承認］［条件付き承認］［修正要求］）で判定し、理由を確定。 |
| **4** | **構造化採点パイプライン** | 対話ログから検証行動を抽出し（第1段階）、その証拠のみを入力に0〜5バンドで客観採点（第2段階）。確信度不足時は人間の確認待ち（`pending_human`）で保留。 |
| **5** | **XAI評価レポート** | 採点根拠となった発言箇所のハイライト、4領域の観測サマリー、受講者の事前判定との対照、異議申立導線を表示。 |

#### 主要画面のスクリーンショット

### 2.2 その他の画面

* **共通アンカー評価**: 全員が同一条件で答える固定設問（SCT型）。状況変化に対する判断更新を4段階で測定（![共通アンカー画面](docs/screenshots/02-anchor-question.png)）。
* **① 組織・受講管理ダッシュボード（モックUI）**: メンバー別の受講進捗、4領域の成長推移、AI鵜呑み率の改善を一元表示（![組織ダッシュボード](docs/screenshots/07-organization-dashboard.png)）。
* **② 受講者スキルカルテ（モックUI）**: 4領域12観点のレーダーチャート、適正依存プロファイル、好手ログを表示（![受講者カルテ](docs/screenshots/08-learner-profile.png)）。
* **③ エキスパート事後講評（モックUI）**: AIが仕掛けた欺瞞の構造、上位者の攻略ルート比較、自律的な復習材料を提供（![エキスパート事後講評](docs/screenshots/09-benchmark-gallery.png)）。

## 3. クイックスタート

リポジトリをクローン後、以下の手順ですぐにローカル起動できます。公開デモ用のサンプル設問が同梱されているため、クローン直後から全画面を体験可能です。

```bash
npm install
cp .env.example .env      # DATABASE_URL は docker-compose の設定と一致
docker compose up -d      # ローカル PostgreSQL（外部 DB を使うなら不要）
npm run prisma:generate && npm run prisma:push
npm run seed:anchors      # サンプルアンカー項目の投入
npm run dev
```

> 💡 **LLM APIキーの設定について**:  
> `.env` に `OPENAI_API_KEY` を設定すると、AI同僚との動的対話演習・2段階自動採点・XAIレポートまで実稼働します。APIキー未設定でも、管理画面・カルテの閲覧や共通アンカー出題・ログ基盤はそのまま動作します。

操作手順の詳細やテレメトリの確認項目は [プロトタイプ動作確認手順書](docs/プロトタイプ動作確認手順書.md) を参照してください。

## 4. 主なコマンド

```bash
npm run dev                   # 開発サーバー起動 (http://localhost:3000)
npm run test                  # 単体テスト（Vitest 242件・APIキー/DB不要）
npm run test:integration      # 結合テスト（Vitest 20件・実PostgreSQLを使用）
npm run test:e2e              # E2Eテスト（Playwright 11シナリオ）
npm run capture:screenshots   # UIスクリーンショット自動取得（docs/screenshots/ へ高解像度出力）
npm run check:flaw-detection  # 代行無効化チェック（Claude / Gemini マルチプロバイダ実測）
npm run check:no-leak         # クライアントバンドルへの正答鍵・秘密情報非漏洩チェック
```

## 5. 技術スタック

* **Frontend**: Next.js 16（App Router）、React 19、Tailwind CSS v4、Lucide React
* **Backend**: Next.js Route Handlers、TypeScript、Zod
* **Database**: PostgreSQL、Prisma ORM
* **LLM**: OpenAI API（既定: `gpt-5.6-luna`）、Anthropic / Google GenAI SDK（検証用）
* **Testing**: Vitest、Playwright
