> **ステータス**: Approved / Implemented
> **対象レイヤー**: 検証用シミュレーション（本番の採点経路には接続しない）
> **全体アーキテクチャ**: [specs/README.md](../README.md)

## 1. 概要とユーザー価値 (What & Why)

### 1.1 解決する課題
第2層の固定設問（共通アンカー）は、第1層の共通尺度 $\theta_{\text{CJ}}$ を LLM の外から確かめる基準である。確かめ方の一つが、$\theta_{\text{CJ}}$ と固定設問の得点の順位相関（到達基準「収束妥当性」：$\rho \ge 0.60$、95%信頼区間の下限 $> 0.40$、受講者60名）である。

観測される相関は、2つの測定の信頼性で頭打ちになる（希薄化）。固定設問の項目が少なければ、仕組みが正しくても基準に届かない。そうなると、基準を満たせなかったときに「構成概念が違う」のか「項目が足りない」のかを区別できない。項目数は、実データを集める前に決めておく必要がある。

### 1.2 提供価値・ゴール
1. 項目数 $L$、1項目あたりの信頼性、2つの構成概念の真の相関、$\theta_{\text{CJ}}$ の信頼性を変えたときに、収束妥当性の基準を満たす確率がどう変わるかを出す。
2. 条件ごとに、基準を満たす確率が 80% に届く最小の項目数を出す。
3. 結果を「固定設問の α（PoC 第1弾で観測できる量）」で読めるようにする。1項目あたりの信頼性は実際の設問で決まる量であり、合成データでは決められないためである。
4. 結果が乱数種で再現でき、仮定したパラメータが結果と一緒に出力される。

### 1.3 この検証が示さないこと（境界）
* **実際の固定設問（v2-sct）の1項目あたりの信頼性は示さない。**本検証はこれを振る。値は PoC 第1弾の応答から推定するしかない。
* **2つの構成概念の真の相関も示さない。**収束妥当性の検査は、まさにこれを確かめるためのものである。
* 所要時間は「1項目45秒〜1分」という見込みからの換算であり、実測ではない。
* 合成データの数値を、到達目標の達成見込みとして引用しない。

## 2. ユーザーストーリーと受入基準 (Acceptance Criteria)

### [US1] 生成モデル
* **Given**: 受講者 $n$ 名に、2つの真値 $(\theta_{\text{CJ}}, \theta_{\text{A}})$ を相関 $r_{\text{true}}$ の2変量正規分布から割り振る。
* **When**: (a) $\theta_{\text{CJ}}$ の観測値を、信頼性 $\text{rel}_{\text{CJ}}$ になるよう誤差を足して作る。(b) 固定設問 $L$ 項目に、4段階（0〜3点）で順序づけられた応答を生成し、合計点を固定設問の得点とする。
* **Then**:
  * 1項目あたりの信頼性（実現値）が、指定した目標値になるように、潜在反応への $\theta_{\text{A}}$ の負荷が較正される。
  * 項目どうしは、$\theta_{\text{A}}$ を通してのみ相関する（1状況文1設問。項目間の局所依存はない）。

### [US2] 1回の試行の集計
* **Then**: 1回の試行ごとに、次を返す。
  * $\theta_{\text{CJ}}$ の観測値と固定設問の得点の Spearman 順位相関 $\hat\rho$
  * その95%信頼区間（Fisher z。標準誤差は Bonett & Wright の $\sqrt{(1+\hat\rho^2/2)/(n-3)}$）
  * 基準を満たしたか（$\hat\rho \ge 0.60$ かつ下限 $> 0.40$）
  * 固定設問の Cronbach の α
  * 希薄化補正後の値 $\hat\rho / \sqrt{\hat\alpha \cdot \text{rel}_{\text{CJ}}}$

### [US3] 条件の格子と最小項目数
* **When**: $L$、1項目あたりの信頼性、$r_{\text{true}}$、$\text{rel}_{\text{CJ}}$ の格子で試行を繰り返す。
* **Then**: 条件ごとに、基準を満たした割合・$\hat\rho$ の平均と5〜95%範囲・α の平均・希薄化補正後の値の平均を出し、割合が 0.80 以上になる最小の $L$ を出す（格子の範囲で届かなければ「届かない」と出す）。

### [US4] 再現性と出力
* `npm run sim:anchor-length` で実行でき、LLM API・DB を使わない。
* 同じ乱数種なら同じ結果を返す。
* `docs/anchor-length-simulation/` に結果の Markdown を書き出し、仮定したパラメータを併記する。
