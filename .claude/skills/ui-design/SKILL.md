# UI設計の規範

このプロダクトの画面は**測定結果を読ませるための計器であり、SaaSのダッシュボードではない。**
読み手は未踏の審査員、大学関係者、B2Bの導入検討者で、いずれも「この数値は信用できるか」を
見に来る。装飾はその判断を助けないばかりか、**測っていることの信頼性を下げる。**

**この文書は禁止リストではなく規範である。**「やってはいけないこと」だけを守ると、減点のない
無難な画面——つまりアマチュアの仕事——にしかならない。プロの画面と分けるのは、階層が
**具体的な数値として決まっていて、画面をまたいで一貫している**ことのほうである。

## 一般論はここに書かない——公開Skillに従う

UI の一般的な作法（視覚設計の方向性、アクセシビリティ、フォーム、インタラクション）は
**自作しない。**すでに専門家がレビューし、何十万件と使われている公開Skillが `.agents/skills/`
に入れてある。**この文書はそれらを前提に、このプロダクト固有の数値だけを定める。**

| Skill | 何に使うか | いつ読むか |
| :--- | :--- | :--- |
| `frontend-design`（Anthropic） | 視覚設計の方向性、**AI生成物の典型的な兆候（tell）の一覧** | 画面を新しく作る前 |
| `web-design-guidelines`（Vercel） | アクセシビリティ・フォーム・パフォーマンスの**実装監査** | 書き終えたあと、レビューとして |
| `emil-design-eng`（Emil Kowalski） | ボタンの押下感、遷移、動きの細部 | 操作の手触りを詰めるとき |

⚠️ **`frontend-design` が名指しする兆候のうち、このリポジトリで実際に出たもの**——
見出しの上に小さいラベルを積む形（eyebrow）、中黒で連結したメタ文字列（`A · B · C`）、
小さな数値ラベルへの等幅書体、すべてを同じ角丸カードに刻む形。**いずれも一度は書いてしまった。**
新しい画面を作るときは、まず `frontend-design` のリストと突き合わせること。

## まずこれをやる

1. `src/app/globals.css` の `@theme` を読む。**色もサイズも余白もここにある名前だけを使う**
2. `src/app/components/ui/` のプリミティブ（`Section` / `Card` / `Button` / `Badge` / `Field`）で組む
3. 書き終えたら `npm run check:ui` を通す（CIでも落ちる）
4. **仕上げに `web-design-guidelines` でレビューを走らせる**——`check:ui` が見るのはこのリポジトリ
   固有の決め事だけで、フォーカス可視化や `prefers-reduced-motion` のような一般則は見ていない

## 書体

`src/app/fonts.ts` で **IBM Plex Sans JP + IBM Plex Mono** を `next/font` 経由で自己ホストしている。

- **システムフォントに戻さない。**Windows では游ゴシックに落ち、`font-semibold` をブラウザが
  合成ボールドで太らせるため見出しの輪郭が潰れる。ウェイトを実際に持つ書体だからこそ
  400 と 500 と 600 の差が階層として読める
- `font-feature-settings: "palt"` を `html` に効かせてある。和文の約物前後の余分な空きが締まる
- ウェイトは **400（本文）/ 500（強調・ラベル）/ 600（見出し）** の3つ。700 は使わない

## 文字の階層——スケールから外れない

サイズ・ウェイト・行間を 1 組で持たせてある。使う側は名前だけ書く。

| 名前 | 実寸 | 何に使うか |
| :--- | :--- | :--- |
| `text-display` | 28px / 600 | 画面名。**1画面に1つだけ** |
| `text-title` | 19px / 600 | 区画（`Section`）の見出し |
| `text-section` | 15px / 600 | 枠（`Card`）の見出し、カード内の小見出し |
| `text-body` | 14px / 400 / 行間1.8 | 読ませる文章 |
| `text-caption` | 13px / 400 / 行間1.7 | 補足・注記・表のセル |
| `text-label` | 12px / 500 | 項目名・メタ情報・ボタン・バッジ |
| `text-data` | 13px / 500 | 数値・ID・ログ（`font-mono` と併用） |

**`text-xs` や `text-[11px]` を書かない。**素の値で書くと、書くたびに判断が発生し、
画面ごとに 11px と 12px と 13px が混ざる。混ざった瞬間に「揃っていない画面」になる。

- 読ませる文章は `max-w-2xl`（約48字）までに抑える。全幅に流すと目線の戻りが長く、読み飛ばされる
- 数値が縦に並ぶ箇所は `data-numeric` を付けて桁を揃える（テーブルは自動）
- 等幅は**機械が吐いた文字列にだけ**使う。ログ、コード、テーブル名、識別子、版数。
  **スコアや件数や日付は数値であって識別子ではない**——桁揃え（`data-numeric`）で足りる。
  小さな数値ラベルに等幅を当てるのは `frontend-design` が名指しする兆候そのものである

## 余白の階層——距離が意味を持つ

| 名前 | 実寸 | 何の距離か |
| :--- | :--- | :--- |
| `section` | 40px | 画面の区画どうし |
| `block` | 16px | 枠の中のブロックどうし |
| `row` | 8px | 並ぶ行どうし |
| `cell` | 12px | セルの内側 |
| `pad` | 20px | 枠の内側 |

`space-y-section` `gap-block` `p-pad` のように書く。**セクションの間とセルの中が同じ 12px だと、
まとまりが目に入らない。**距離の差そのものがグルーピングを伝える。

## 装飾の予算——全部をカードにしない

`border` / 地色 / `radius` はどれも「ここは別の物体だ」と言う。全部に同じ枠を付けると
言葉が効かなくなり、画面は「フォームの集合」に見える。**3階層に配分する。**

| 階層 | 使うもの | 装飾 |
| :--- | :--- | :--- |
| 1. 画面の区画 | `<Section>` | **枠なし。**見出し（`text-title`）と `space-y-section` だけで区切る |
| 2. データのまとまり | `<Card variant="panel">` | 罫線 + 白地 + `rounded-card` |
| 3. 枠の中の塊 | `<Card variant="inset">` / `bg-surface-sunken` | **地色のみ。罫線は引かない** |

- 入れ子は **panel → inset の2段まで。**3段目が要るなら情報の切り方が間違っている
- 影は使わない。階層は罫線と地色の1段差で表す
- 「ラベルと値の並び」に枠は要らない。罫線1本（`divide-y divide-line`）で足りる

## 色——役割で呼ぶ

Tailwind 既定のパレットは `--color-*: initial` で落としてある。`bg-slate-900` は存在しない。

| 役割名 | 用途 |
| :--- | :--- |
| `surface` / `surface-sunken` / `surface-page` | 面。沈めたい領域だけ1段落とす |
| `line` / `line-strong` | 罫線。**階層は影ではなく線で作る** |
| `ink` / `ink-2` / `ink-3` | 文字。3段まで |
| `accent` / `accent-hover` / `accent-wash` | 唯一のアクセント（濃紺） |
| `positive` / `caution` / `critical`（＋`-wash`） | **状態を表すときだけ。**装飾や分類には使わない |

ニュートラルはアクセントの濃紺へわずかに寄せた青灰にしてある。純グレーは「選ばなかった色」に見える。

### 状態には色を使う——絞りすぎると走査できなくなる

**装飾に色を使わないことと、状態に色を使わないことは別である。**一覧の数字が全部同じ濃さの黒で
並ぶと、読み手は走査ではなく精読を強いられる。**情報量が多い画面ほど、どこを見るべきかを色で
示す必要がある。**意味色はアクセントとは別枠であり、アクセントを1色に絞る規律とは衝突しない。

判定は `src/app/components/ui/tone.ts` の `thresholdTone(value, { good, poor, higherIsBetter })` に
寄せる。⚠️ **符号で判断しない**——「盲従バイアス克服率 −28.4 pt」は無検証承認率が下がった
**良い**変化であり、「過剰指摘率 +5 pt」は**悪い**変化である。指標ごとの良い向きを渡すこと。

### 見えなければハイライトではない

⚠️ **暗く落とした意味色は、小さな数値に当てても本文の黒に紛れる。**色を付けた気になるだけで、
走査の手がかりにならない。2つの決め事でこれを防ぐ。

1. **意味色は黒から離れるところまで彩度を上げる**（白地に対する読みやすさ 4.5:1 は保つ）
2. **要注意の側にだけ面を敷く**——`toneChip()` は `caution` / `critical` にだけ地色を返し、
   `positive` は文字色だけを返す。**良好が多数派の一覧で良好に面を付けると画面が埋まり、
   かえって何も目立たなくなる。**手当てが要る値は数が少ないので、面を敷いて初めて拾える

一覧の中の値は `toneChip()`、文中の一語は `toneText()` を使う。

使う場面:

- **閾値を跨いだ値**——完了率 90%以上は `positive`、80%未満は `caution`。**その間は無彩色で沈める**
- **到達水準の3段**——Band 4以上 `positive` / Band 3 `accent` / それ未満 `caution`
- **手当てが要る行**——左に 2px の帯（`border-l-2 border-l-caution`）を引く
- **向きのある指標**——改善後のバーは `positive`。「高いほど良い」が決まっている量にだけ

使わない場面:

- **種類の区別**（4領域に4色を割り当てる）
- **連続量そのもの**への色付け（Band の数値に濃淡を当てる。序列は数値が示す）
- **まだ選んでいない選択肢**（承認を緑・却下を赤に塗ると、選ぶ前に画面が結論を示唆する）

## 書かないもの と 代わりに書くもの

| 書かない | 代わりに |
| :--- | :--- |
| `text-xs` `text-[11px]` `text-sm` | スケールの名前（`text-caption` など） |
| `p-3` `space-y-6` などの素の値 | 役割名（`p-cell` `space-y-section`） |
| `bg-gradient-to-r from-blue-600` | `bg-accent`（単色） |
| `shadow-lg shadow-blue-500/25` | `border border-line` |
| `glass-panel` / `backdrop-blur` | `bg-surface` + 罫線 |
| `animate-pulse` の点灯表示 | 静的なドット、または `Badge` |
| `rounded-xl` / `rounded-2xl` | `rounded-card` |
| `uppercase tracking-wider` の英字ラベル | `text-label` の日本語 |
| `<Sparkles />` `<Zap />` などの装飾アイコン | 置かない。見出しは文字だけで足りる |
| 絵文字（⚡ ✨ 🚀 ✅ ⚠️）| `Badge` か、語で書く（工程を示す矢印 ➔ は文言の一部なので可） |
| 4領域に4色を割り当てる | ニュートラルで並べ、区別は文字で付ける |

**アイコンは意味を運ぶときだけ置く。**閉じる（`X`）や処理中（`RefreshCw` + `animate-spin`）は残す。

## 情報量は削らない

README が明示する通り1画面あたりの情報密度は意図的である。**洗練とは要素を減らすことではなく、
読む順序を付けること。**手段は3つに限る——**大きさ**（スケール）、**濃さ**（`ink` の3段）、
**距離**（余白の階層）。色で階層を作らない。色を足すほど、どれが重要なのか分からなくなる。

ダッシュボードは読み物ではなく**走査して操作するもの**である。要約を詳細より前に置き、
注意が要る状態は数値ではなく形（`Badge`）で示す。

## チャート

このリポジトリのチャートはいずれも**1系列**である（レーダー1枚、横バー2種）。

- 系列が1本なら凡例は要らない。タイトルか軸ラベルが系列名を兼ねる
- **カテゴリカル配色を作らない。**4領域に4色を割り当てると、領域間に良し悪しの序列が
  あるように読める
- 量を表すバーはアクセント1色。比較対象（Before / After など）は片方を罫線色に沈める
- グリッドと軸は `--color-line` まで落とす。色を持つのは塗りと線だけ
- **読めない大きさの図は置かない。**カードが12枚並ぶ場所のバーは20px幅にしかならず、
  それは情報ではなく飾りである。数値で足りるなら数値にする

## テストとの付き合い方

E2E は `getByText` と `getByRole` が中心なので、**画面の文言を変えない限り見た目の改修では
壊れない。**文言はテストとの契約でもあるので、短くしたくなっても勝手に変えない。

配色のクラス名（`span.bg-purple-500/20` など）を掴んでいるテストがあったら、それはテスト側の
誤りなので `data-testid` へ付け替える——見た目に依存したテストは、デザインを変えるたびに壊れる。

## タブは折り返す前提で選ぶ

下線式のタブ（`-mb-px` + `border-b-2`）は**1行に収まる短いラベルにだけ使う。**折り返すと
上の行の下線が親の罫線から離れて宙に浮き、下の行と重なる。

項目名が長いなら、**下線ではなく面で選択を示す**（枠 + `bg-accent-wash` のカード型）。
折り返しても壊れず、長い文字列も2行で収まる。
